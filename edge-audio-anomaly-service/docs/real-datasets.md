# Real Industrial Audio Datasets

This project now supports public industrial audio folders without making those
large datasets part of Git. The local sample generated by
`scripts/evaluate_public_audio_dataset.py` is only a MIMII-shaped fixture for
offline testing; final claims should use real downloaded data.

## Recommended Datasets

- MIMII Dataset: Sound Dataset for Malfunctioning Industrial Machine
  Investigation and Inspection. Official record:
  https://zenodo.org/records/3384388
- ToyADMOS: miniature-machine operating sounds for anomalous sound detection.
  Dataset page: https://www.ksuke.net/dataset/toyadmos and Zenodo record:
  https://zenodo.org/records/3351307

## Supported Folder Shapes

The loader recursively scans WAV files and labels them from path segments:

```text
fan/id_00/train/normal/*.wav
fan/id_00/test/normal/*.wav
fan/id_00/test/abnormal/*.wav
```

Also supported:

```text
normal/*.wav
anomaly/*.wav
abnormal/*.wav
train/normal/*.wav
test/anomaly/*.wav
```

Label rules are intentionally simple:

- `normal`, `healthy`, `ok` -> normal
- `abnormal`, `anomaly`, `anomalous`, `fault`, `faulty`, `broken` -> anomaly
- `train`, `training` -> training split
- `test`, `testing`, `eval`, `evaluation`, `dev` -> evaluation split

## Commands

Generate and evaluate the built-in MIMII-shaped fixture:

```powershell
..\tinyml-predictive-maintenance\.venv\Scripts\python.exe scripts\evaluate_public_audio_dataset.py
```

Evaluate a real downloaded folder:

```powershell
..\tinyml-predictive-maintenance\.venv\Scripts\python.exe scripts\evaluate_public_audio_dataset.py --data-root E:\datasets\MIMII\fan
```

Outputs:

- `reports/public_audio_evaluation.md`
- `reports/public_audio_evaluation.json`

## Interview Framing

Use the generated sample to prove the code path runs offline. Use real
MIMII/ToyADMOS data for any serious metric claim. That distinction is important:
the project is stronger when it is honest about synthetic fixtures versus public
benchmark data.
